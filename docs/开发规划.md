## 1. 项目定位与边界

### 1.1 做什么

| 能力域 | 说明 |
|---|---|
| 源格式兼容 | Legado 书源（含漫画源/订阅源）、TVBox 配置（sites/lives/parses/drives）、ZyPlayer 一键格式、eso 源、海阔视界源、drpy（XP/JS 源） |
| 标准接口对接 | 苹果 CMS 资源站（json/xml）、飞瓜/DJ 资源接口、IPTV m3u/txt、genre 电台、xmltv EPG 节目单 |
| 规则语法 | 全选择器体系：JSoup 类选择器、CSS、XPath、JSONPath、正则、`{{}}` JS 模板、`@js:`/`<js>` 纯 JS |
| 消费端 | 观影界面（多播放器/换源）、阅读界面（翻页/排版/朗读）、直播界面（EPG/换台） |
| 工具链 | 规则编写界面 + 分步调试器 + 源体检（批量校验可用性） |

### 1.2 不做什么（关键边界）

- **不内置任何源**（学 legado/zyplayer：空壳发行，源由用户自行导入）。
- 不做内容存储与分发：只做「解析与呈现」，不缓存媒体本体。
- PC 端不追求安卓端复刻：聚焦 Web/PC 体验，移动端留作远期。
- **v1 主线不支持 Python 脚本源**。Py 源生态小众、实现成本高、浏览器端无法执行；将其列为远期 v2+ 桌面侧车（Sidecar）可选能力。
- **v1 主线不支持 DLNA/投屏**。该功能为边缘需求，增加复杂度且体验难以保证；列入远期规划。

### 1.3 核心价值

用户无需在多个应用间切换，即可访问书籍、漫画、视频、直播、订阅源等多种内容。强大的规则兼容性让用户可以复用现有的大量社区资源。

### 1.4 设计原则

| 原则 | 说明 |
|------|------|
| **模块化** | 规则引擎、解析引擎、播放器相互独立 |
| **可扩展** | 适配器模式，易于添加新源格式 |
| **跨平台** | Web + PC 双端同构，一套规则引擎两端运行 |
| **同构优先** | 核心引擎纯 TS 实现，双端共用一套代码 |
| **安全沙箱** | 用户脚本严格隔离，防止恶意代码 |
| **开源友好** | GPL-3.0 协议，完善的开发者文档 |

## 2. 竞品分析与差异化

### 2.1 参考项目技术解构

| 参考项目 | 它的强项 | 我们借鉴什么 | 它的局限（我们的机会） |
|---|---|---|---|
| **legado** | 规则引擎设计（AnalyzeRule 前缀路由）、书源生态 | 规则语法与解析管线 | 纯安卓、WebDAV 同步原始、桌面缺失 |
| **TVBox** | 配置生态（一键接口）、CMS 对接约定 | sites/lives/parses 配置模型、嗅探播放 | 闭源分支林立、spider.jar 依赖 Java |
| **海阔视界 HikerView** | 纯 JS 规则 + 内置代码编辑器、调试体验 | JS 宿主 API 设计思路 | 仅开放核心模块、规则可移植性差 |
| **eso** | 轻量 JS 源范式 | `search/home/detail/play` 函数式源接口 | 停更风险、生态小 |
| **ZyPlayer** | Electron 桌面端体验、一键格式 | 桌面端交互、CMS/EPG 实践 | 源类型少（CMS+IPTV 为主）、无规则引擎 |

### 2.2 差异化定位

**市场空缺 = 「桌面级体验 + 全格式规则引擎 + 可视化调试」**

这是本项目的技术护城河：

- **跨平台**：Web + PC 双端同构，一套规则引擎两端运行。
- **全格式兼容**：覆盖 Legado/TVBox/海阔/eso/drpy/CMS/IPTV 七大生态。
- **可视化调试**：分步执行时间线 + 变量观察 + 网络回放，规则开发效率提升一个数量级。
- **统一换源**：智能指纹归并，影视/书籍一键换源，进度无缝衔接。

### 3.3 架构铁律

**依赖方向**：`apps → packages/ui → packages/core ← engine-js/player/reader`

## 4. 核心技术选型

### 4.1 技术选型决策记录 (ADR)

| # | 决策 | 选择 | 理由 | 放弃项 |
|---|---|---|---|---|
| D1 | 前端框架 | **Vue 3 + TypeScript + Vite** | 生态成熟、ZyPlayer 验证过桌面路径 | React（无决定性优势） |
| D2 | PC 端 | **Tauri v2**（主方案），Electron 为备选 B | 包体 ~10MB（Electron ~120MB）、Rust 侧原生能力（代理/进程）、复用 Web 壳；Electron 备选用于需要大量 Node-API 原生扩展的场景 | Electron（重）、Flutter Desktop（UI 无法复用） |
| D3 | JS 规则沙箱 | **quickjs-emscripten（WASM）** | 双端**同构执行**（一处实现两处运行）；规则生态里 JS 语义与 legado 的 Rhino 最接近；可限时/限内存 | Web Worker vm（浏览器可逃逸到 DOM）、Node vm（桌面专用破坏同构） |
| D4 | HTML 解析 | **cheerio（服务无关实现）** | 与 jQuery 选择器语义一致，最贴近 JSoup 行为 | linkedom（对边缘 HTML 容错差） |
| D5 | XPath | **xmldom + 自研 xpath**（或 wgxpa） | 纯 TS、双端可用 | 浏览器原生 XPath（仅 DOM 端） |
| D6 | 数据层 | **repo 接口 + 双驱动**（Dexie/IndexedDB 与 Tauri SQLite） | 上层无感 | localStorage（量级不够） |
| D7 | 播放器 | **ArtPlayer 封装 + hls.js + dash.js + flv.js** | 插件式架构、嗅探扩展易写 | video.js（UI 定制重）、XGPlayer（协议覆盖弱） |
| D8 | Web 端网络 | **自部署 Node 代理（默认关闭，可自建）** + 桌面端直连 | 合规且灵活 | 公共 CORS 代理（不可控） |
| D9 | 代码编辑器 | **Monaco Editor** | 桌面级体验、自定义语法高亮/智能补全可注册 | CodeMirror6（补全生态弱） |
| D10 | 后端形态 | server 为**可选独立包**，核心不依赖 | 桌面端零后端 | 强制中心化后端（单点+审查风险） |
| D11 | 组件库 | **Element Plus** | Vue3 生态最成熟、组件丰富、中文文档完善 | TDesign（社区资源相对少）、Arco Design |
| D12 | 状态管理 | **Pinia** | Vue3 官方推荐，TypeScript 友好，API 简洁 | Vuex（已过时）、Redux（过重） |

**关于 Tauri v2 vs Electron 的补充说明**：

- 默认采用 Tauri v2，以获得更小包体与 Rust 侧进程能力。
- 若后续需要深度绑定 Node-API/C++ 扩展（如高性能视频解码、专属协议驱动），可评估 Electron 作为桌面备选方案；Web 壳与 core 包完全复用，迁移成本可控。

| **ZyPlayer 源** | JSON + API | 不支持 | 不支持 | 原生 | 不支持 | 部分 | 中 | 低 |

### 5.1 导入方式

- **本地文件导入**：支持 JSON / M3U / TXT 格式。
- **网络 URL 订阅导入**：支持 HTTP/HTTPS 链接，自动更新。
- **剪贴板粘贴导入**：直接粘贴 JSON 文本或 URL。
- **一键格式导入**：TVBox 一键接口、ZyPlayer 一键格式。

## 6. 源格式深度分析

### 6.1 四种源范式

```
范式A 声明式规则  → Legado 书源 / 漫画源 / 订阅源
                    （JSON 结构化字段 + 规则字符串，宿主解释执行）
范式B 纯JS逻辑源  → hiker / eso / drpy
                    （整站逻辑写成一坨 JS，宿主提供 API）
范式C 标准API     → 苹果CMS(json/xml) / 资源站 vod 接口
                    （固定接口协议，按文档直连）
范式D 纯数据源    → IPTV m3u / txt / xmltv EPG / 订阅(RSS/OPDS)
                    （无需解析逻辑，解析文本即内容）
```

**架构判断**：**A 与 C 可统一为「管道描述」，B 需要「JS 沙箱宿主」，D 是「导入器」。** 这决定了引擎三分：`RulePipeline` + `JsRuntime` + `Importer`。

### 6.2 Legado 书源结构（范式A核心）

```jsonc
{
  "bookSourceUrl": "https://example.com",
  "bookSourceName": "示例源",
  "bookSourceType": 0,
  "bookSourceGroup": "玄幻,排行榜",
  "searchUrl": "/search?kw={{key}}&page={{page}}",
  "exploreUrl": "玄幻::/sort/1\n都市::/sort/2",
  "ruleSearch": {
    "bookList": "class.bookbox@tag.div",
    "name": "tag.h1@text",
    "author": "tag.span@text",
    "coverUrl": "tag.img@src",
    "bookUrl": "tag.a@href"
  },
  "ruleBookInfo": { "init": "<js>...</js>", "name": "...", "tocUrl": "..." },
  "ruleToc":    { "chapterList": "...", "chapterName": "...", "nextTocUrl": "..." },
  "ruleContent":{ "content": "id.content@textNodes", "nextContentUrl": "..." },
  "loginUrl": "...", "header": {}, "enabled": true
}
```

### 6.3 规则前缀路由

| 规则前缀 | 引擎 | 示例 |
|---|---|---|
| 无前缀 | JSoup 类选择器 | `class.content@tag.p@text` |
| `@css:` | 标准 CSS Selector | `@css:.book-list>li>a@text` |
| `//` | XPath | `//div[@class="list"]/a/text()` |
| `$.` | JSONPath | `$.data.list[*].name` |
| `:` | 正则捕获 | `:search\("(.+?)"\)` |
| `@js:` / `<js></js>` | 纯 JS | `@js:result.replaceAll('x','')` |
| `{{...}}` | JS 内插 | `url:{{baseUrl}}/page/{{page}}` |
| `&&` / `\|\|` | 规则连接 | `rule1\|\|rule2` |

### 6.4 TVBox / CMS 配置（范式C）

```jsonc
{
  "sites": [{
    "key": "xx", "name": "xx站", "type": 0,
    "api": "https://x/api.php/provide/vod/",
```

- `sites.data[].type`: 0=cms(xml), 1=cms(json), 2=drpy, 3=app(v3 私有，忽略)。

- `analyzes[]` → 解析接口池。

### 6.6 hiker / eso / drpy JS 源（范式B）

| 宿主 | 规则形态 | 我们要模拟的宿主 API |
|---|---|---|
| **hiker** | 整页 JS，产出 `d` | `fetch/req`、`parseDom`、`PDFA/PDFH`、`setResult` |
| **eso** | 导出对象 `{ search, home, category, detail, player }` | `req()`、`pdfh()`、`cheerio`、`crypto` |
| **drpy** | `var rule = {...}` 对象 | 引入兼容垫片层 `@omniflow/drpy-shim`，提供 PDFH/PDFA/PDFS |

### 6.7 IPTV / EPG（范式D）

- **M3U**：`#EXTINF:-1 tvg-id="cctv1" tvg-name="CCTV1" group-title="央视",CCTV-1`。
- **TXT**：`央视,#genre#\nCCTV1,http://...`。
- **EPG**：xmltv `<programme start="..." stop="..." channel="cctv1">`。

### 6.8 py 源（执行边界）

Python 脚本源无法在浏览器执行。**v1 主线不提供支持**；仅作为远期 v2+ 桌面侧车进程的可选能力。Web 端明确标注「此源类型仅桌面远期版可用」。

### 7.2 规则管道定义

```typescript
interface RulePipeline {
  search?:  Stage<{ key: string; page: number }, SearchItem[]>;
  explore?: Stage<{ key: string; page: number }, ExploreItem[]>;
  detail?:  Stage<string, DetailResult>;
  toc?:     Stage<string, Chapter[]>;       // 书源目录 / 剧集列表共用
  content?: Stage<string, string[]>;        // 正文/播放地址（含下一页续链）
  next?:    ContinuationRule;               // nextTocUrl/nextContentUrl 续链
}

interface Stage<I, O> {
  request:  RequestTemplate;   // {{key}} {{page}} 模板 + method/headers/body/charset
  list?:    RuleNode;          // 列表选择
  fields:   Record<keyof O, RuleNode>;   // 每个产出字段一条规则
  js?:      { pre?: string; post?: string };  // <js> 前后钩子
}

interface RuleNode {           // 单条规则编译为「段-步」执行计划
  segments: Segment[];         // L1：&& / || 切出的段
  join: 'or' | 'and';          // || 先命中即用；&& 串联传递
}

interface Segment {
  mode: 'jsoup'|'css'|'xpath'|'json'|'regex'|'js';
  steps: Step[];               // L3：步骤流水线
  post: Transform[];           // L4：##正则## / replaceRegex / format / reverse
}
```

### 7.3 规则编译执行流

```
原始规则字符串
  ├─ 切分 && / || → fallback 链
  ├─ 提取 {{...}} → 交给 JsRuntime 求值 → 回填
  └─ 前缀识别:
      '@css:' → cheerio.select        '$.'   → jsonpath 库
      '//'    → xpath 引擎            ':'    → regex 捕获
      '@js:'|'<js>' → JsRuntime        (无前缀) → JSoup 模拟器
  → 统一输出 AnalyzeResult { list, single, text, nodes }
  → transforms 依次应用 → 产出字段
```

## 8. 规则引擎详解

### 8.1 规则执行模型 v2（段-步两级流水线）

> 修订原因：真实社区书源的规则几乎从不「纯」。一条 `ruleContent.content` 完全可能是
> `id.content@textNodes##(\s*<br\s*/?>\s*)+##\n||$.data.content&&@js:result.trim()`
> （JSoup 选段 + 正则净化 + JSONPath 备用 + JS 后处理）。v1 的「前缀→单一路由」模型无法表达，升级如下。

```
L1 段级切分 splitSourceRule：按 && / || 切段（{{}} 与 <js> 块内的分隔符不参与切分）
    → || 语义：先命中即用（fallback 链）
    → && 语义：串联传递 —— 前段输出 = 后段输入
L2 段首 mode 判定（每段独立判一次，段间可切换 mode）：
    `$.` / `$[` → JSON 段        `//` / `@XPath:` → XPath 段
    `@js:`      → 纯JS 段        `:` 开头          → 正则段
    其余（无前缀）→ JSoup 段（默认）
L3 段内步骤流水线（JSoup 段的精髓，按 @ 切步，输入=上一步输出）：
    class. / tag. / id. / text. / children. 伪选择步骤
    ＋ @css: 步骤（cheerio，可出现在任意位置）
    ＋ 中段 <js>...</js> 块（JS 输出字符串/HTML → 继续被后续步骤消费）
    ＋ {{...}} 内插（发生在任何一层的任何步骤）
L4 段级后处理（任何 mode 的段都可挂）：
    ##regex##replacement##（正则替换）/ replaceRegex / format / reverse / join
L5 全局上下文与变量（贯穿所有段与字段）：
    @put:{} / @get:{} / java.put / java.get 跨规则共享
    baseUrl / page / key / result / 每步骤快照（喂给调试器）
```

**v1→v2 五个关键修正**：

| # | v1（错误/简化） | v2（修正） |
|---|---|---|
| 1 | 整条规则判一次 mode | **段级**判 mode：`A规则||B规则` 两段可以分别是 JSoup 和 JSONPath |
| 2 | JSoup 段视为整体 | JSoup 段内部是**多步流水线** |
| 3 | `&&` 理解为结果拼接 | `&&` 是**串联传递**：前段输出作为后段输入 |
| 4 | `{{}}` 只在开头求值 | `{{}}` 在**每一层每一步**都先求值 |
| 5 | 测试语料不分层 | 兼容性回归语料按**混合度分层**：纯规则 / 二混 / 三混以上 |

### 8.2 选择器引擎

```typescript
class SelectorEngine {
  private cssEngine: CssSelector;
  private xpathEngine: XPathSelector;
  private jsonPathEngine: JsonPathSelector;
  private jsoupSimulator: JSoupSimulator;

  executeChain(html: string | object, chain: SelectorChain, ctx?: JSContext): AnalyzeResult {
    let current = html;
    for (const step of chain.chain) {
      switch (step.type) {
        case 'css':      current = this.cssEngine.select(current as string, step.selector); break;
        case 'xpath':    current = this.xpathEngine.select(current as string, step.selector); break;
        case 'jsonpath': current = this.jsonPathEngine.query(current as object, step.selector); break;
        case 'jsoup':    current = this.jsoupSimulator.select(current as string, step.selector); break;
        case 'text':     current = this.extractText(current as Element); break;
        case 'js':       current = ctx?.execute(step.code, { result: current }); break;
        case 'match':    current = this.regexMatch(current as string, step.pattern); break;
        case 'replace':  current = (current as string).replace(new RegExp(step.pattern), step.replacement); break;
      }
    }
    return this.normalizeResult(current);
  }
}
```

### 8.3 JSoup 模拟器

Legado 的核心特色 —— 类 JSoup 的选择器语法：

```
格式: 类型.值.索引@动作
  类型: class / id / tag / text
  值: 类名/ID/标签名/文本内容
  索引: 第几个匹配项（负数从后往前数）
  动作: @text / @html / @textNodes / @ownText / @href / @src / @all

示例:
  class.book-item.0@tag.a@text
  id.content@textNodes
  tag.div.-1@html
```

### 8.4 请求调度器

```typescript
class HttpPipeline {
  private cookieJar: CookieJar;
  private proxyConfig?: ProxyConfig;
  private concurrencyLimit = 5;
  private cache: RequestCache;

  async execute(request: UnifiedRequest, ruleScripts?: RuleScripts): Promise<UnifiedResponse> {
    if (ruleScripts?.preRequest) {
      request = await this.jsRuntime.execute('preRequest', request);
    }
    const req = this.buildRequest(request);                  // 模板变量替换
    const response = await this.withCache(req, () =>
      this.withRetry(() => this.withConcurrency(() => this.httpClient.execute(req)),
        { maxRetries: request.retry || 3 })
    );
    const decoded = this.decodeResponse(response, request.charset);  // 编码处理
    let body = decoded.body;
    if (ruleScripts?.postParse) {
      body = await this.jsRuntime.execute('postParse', { result: body });
    }
    return { body, headers: response.headers, status: response.status };
  }
}
```

### 11.6 两栏布局约定（书架 / 影视 / 书院 / 影院 / RSS 通用）

上述 5 屏共用同一套「左栏 + 右栏」骨架。**分隔线一律顶到卡片边框**（用负 margin 抵消卡片内边距），不使用内缩的短横线：

```text
左栏                              右栏
┌──────────────────────┐          ┌───────────────────────────────┐
│ 书库分组              │          │ 全部书籍 10本  [移动][排序…]   │
│ ════════════════════ │          │ ═════════════════════════════ │
│ ≡ 全部           10  │          │  ▣ ▣ ▣ ▣ ▣   卡片网格         │
│ ○ 未分组          4  │          │  ▣ ▣ ▣ ▣ ▣   （内部滚动）     │
│ ▣ 玄幻            2  │          │                               │
│ ＋ 新建分组          │          │                               │
│ ════════════════════ │          │                               │
│ [    管理分组    ]   │          │                               │
└──────────────────────┘          └───────────────────────────────┘
```

| 要素 | 约定 |
|---|---|
| 左栏宽度 | 书架 / 影视 2450px；书院 / 影院 / RSS 245px（定宽，不随内容伸缩） |
| 左栏结构 | 标题 → 分隔线（全宽）→ 列表（内部滚动）+ 新建 → 分隔线（全宽）→ 底部操作按钮 |
| 右栏结构 | 头部（标题 + 计数居左，工具区居右，**滚动时固定不动**）→ 分隔线（全宽）→ 内容网格（内部滚动） |
| 发现页左栏 | 顶部为「筛选输入框 + 搜索图标」，图标与顶栏全局搜索框同款（15px，`--muted` 色） |
| 滚动策略 | 列表区与内容区各自独立滚动；页面整体不随内容撑长 |

## 14. 风险识别与应对

| 风险 | 等级 | 影响 | 缓解措施 |
|-----|------|------|---------|
| **legado 规则语法边缘 case 无穷** | 高 | 部分规则无法解析 | 兼容性回归语料库（社区规则抽样）+ `@js:` 兜底；不追求 100%，目标 95% 可用 |
| **hiker/drpy 宿主 API 长尾** | 高 | 部分 JS 源无法运行 | 垫片层渐进实现 + 未知 API 调用时在调试器给出明确「未实现 API」提示 |
| **Web 端 CORS 是硬墙** | 中 | 浏览器无法直接请求部分源 | 桌面端直连为主战场；Web 端引导自建 server；公共代理仅限演示 |
| **视频平台解析的法律灰色** | 中 | 可能涉及版权争议 | 仅实现「解析接口配置」机制，仓库不含任何解析地址；文档明示合规边界 |
| **QuickJS 同步桥性能** | 中 | 大量同步请求可能卡顿 | M2 设性能验收线（单源规则执行 P95 < 800ms）；不达标改双通道（桌面走 native） |
| **TVBox Spider 兼容** | 高 | TVBox 大量源用 `type=3` JS Spider | 优先支持 `type=0/1` 直链源；Spider 源明确标记不支持，引导用户寻找直链源 |
| **规则版权/合规** | 中 | 聚合内容可能涉及版权争议 | 工具本身不提供内容，仅解析用户导入的规则；README 首屏免责声明 |
| **单人开发战线过长** | 高 | 开发周期可能延长 | 严格按里程碑裁剪：M1 后即可招募社区共建（规则兼容性最适合众包） |
| **py 源 / DLNA 投屏需求** | 低 | 用户期望与实现边界冲突 | 在 README 与设置页明确标注「v1 不支持，列入远期规划」 |

## 附录 B：规则语法手册

### B.1 选择器类型速查

| 前缀 | 类型 | 示例 | 说明 |
|-----|------|------|------|
| (无) | JSoup 类 | `class.book@tag.a@text` | 兼容 Legado 原生语法 |
| `@css:` | CSS 选择器 | `@css:.book-list > li a@text` | 标准 CSS 选择器 |
| `//` | XPath | `//div[@class="list"]/a/@href` | 标准 XPath 表达式 |
| `$.` | JSONPath | `$.data.list[*].name` | JSON 路径查询 |
| `:` | 正则 | `:url=(.+?)&` | 正则捕获，默认第一组 |
| `@js:` | JS 脚本 | `@js:result.replace(/\s/g,'')` | 内联 JS 处理 |
| `<js>...</js>` | JS 块 | `<js>return result.toUpperCase()</js>` | 多行 JS 脚本 |
| `{{...}}` | 模板变量 | `{{baseUrl}}/page/{{page}}` | URL 模板插值 |

### B.2 动作后缀

| 后缀 | 说明 |
|-----|------|
| `@text` | 提取文本内容 |
| `@html` | 提取 innerHTML |
| `@textNodes` | 提取所有文本节点 |
| `@ownText` | 提取自身文本（不含子元素） |
| `@href` | 提取 href 属性 |
| `@src` | 提取 src 属性 |
| `@data-src` | 提取 data-src 属性 |
| `@all` | 提取所有匹配 |

### B.3 规则组合

- `&&`：与连接，依次执行，全部生效（串联传递）。
- `||`：或连接，从左到右尝试，取第一个成功结果。

### B.4 净化函数

| 函数 | 说明 |
|-----|------|
| `replaceRegex!pattern!replacement` | 正则替换 |
| `reverse` | 反转字符串 |
| `format(template)` | 格式化输出 |
| `trim` | 去除首尾空白 |
